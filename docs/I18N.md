# Internationalization

i18n status: Applies — deferred to the owner's locale decision in #27

Reason: INTERNATIONALIZATION-STANDARD §1's N/A test is not met. The site
serves the public, and it shows end users game dates and start times
(English month and weekday names, 24-hour times, venue time zones). It is
English-only by design so far, and it is not a civic or public-service
surface. Whether to add a locale is a product decision that is still open.
Montréal Victoire's audience is the obvious candidate.

What holds today, without a catalog:

- Every page is UTF-8 and declares `<html lang="en">`. axe's `html-has-lang`
  and `html-lang-valid` rules run on every page in `make a11y`.
- Game times are shown in the venue's own IANA time zone, from Ticketmaster
  data. Calendar feeds carry TZIDs, so calendar apps localize them.
- Time-zone data comes from the `tzdata` package pinned in `pipeline/uv.lock`.

Entry point if a locale is added: wrap user-facing strings in
`pipeline/src/wsc_pipeline/site.py` in `_()` (gettext, a `locales/`
catalog), render one page tree per locale with the right `lang`, and wire
the §4 AUTO-GATEs into `make verify`. See
`docs/standards/INTERNATIONALIZATION-STANDARD.md` §3.
